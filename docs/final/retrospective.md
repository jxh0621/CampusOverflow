# Sprint 回顾总结

## Sprint 1 回顾（问答闭环）

### 做得好
- 领域模型设计合理，Question/Answer/Vote/Comment 边界清晰
- 工厂方法+reconstitute 模式正确，不变式在领域层守护
- 标签差量更新逻辑考虑周到

### 待改进
- 标签计数 bug 后期才发现，单元测试覆盖不够
- 应用层测试应该和开发同步写，不要堆到最后

## Sprint 2 回顾（声誉激励）

### 做得好
- 幂等设计到位：账本唯一键(eventId,userId,reason)保证事件重放不重复
- 每日上限用差值计算，边界清晰
- Bounty 状态机 OPEN→AWARDED/EXPIRED 终态不可变

### 待改进
- 应用层测试起步晚，应该在开发时同步写
- Redis 排行榜和数据库对账需要更多边界测试

## Sprint 3 回顾（内容发现）

### 做得好
- 行走骨架策略有效：先用空实现跑通端到端，再逐步填充
- 事件投影模式清晰：每个事件处理器幂等标记已处理

### 待改进
- 端到端测试应该在 Sprint 1 就开始搭框架，不要等到 S3
- 中文搜索分词的边界case需要更多测试

## 团队协作经验
1. **分支保护必须第一天就开**：否则有人直接push main
2. **PR 小步走**：一个任务一个PR，不要攒大PR
3. **测试先行**：红→绿→重构，不要先写实现再补测试
4. **CI 早绿**：不要让红灯挂太久，阻塞集成
5. **文档随代码走**：每个PR同时更新相关文档，不要最后补
